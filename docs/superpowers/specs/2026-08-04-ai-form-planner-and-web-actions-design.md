# AI 表单规划器与可选网页操作设计

## 背景与目标

现有自动填写链路主要依赖本地字段启发式，并只把未匹配字段交给 AI。AI 看不到页面章节、重复经历条、添加按钮以及动态控件之间的关系，因此无法可靠处理“先添加项目条，再按顺序填写多个项目”一类招聘页面。

本功能增加通用 AI 表单规划器：插件遍历当前招聘表单，生成脱敏、紧凑、带稳定临时 ID 的页面语义快照；AI 只返回引用这些 ID 的结构化动作与字段映射；本地执行器验证并执行计划。默认模式只填写和创建重复经历条，用户可主动开启“允许 AI 操作网页”模式处理折叠面板、标签页、日期控件、联动下拉和下一步。

目标如下：

- 覆盖不同招聘系统的原生和 ARIA 表单控件，而非按域名硬编码。
- 识别项目、实习/工作、教育、获奖等重复章节及其添加按钮。
- 按资料数组顺序创建并填写经历条，避免跨条目重复。
- 让 AI 理解页面语义，但由本地代码掌握执行权和安全边界。
- 控制请求体、调用次数和 DeepSeek Flash 使用成本。
- 所有页面映射、权限与操作日志只保存在本机浏览器。

## 方案比较

### 方案 A：AI 规划器 + 本地受限执行器（采用）

本地扫描器生成语义快照，AI 返回结构化计划，本地验证器按元素 ID 执行。该方案兼顾通用性、可测试性、安全性和成本，并能复用现有扫描器、资料路径和字段填写器。

### 方案 B：AI 直接返回 CSS、XPath 或 JavaScript

实现较快，但选择器易受页面改版影响，模型可能引用不存在或错误的节点，任意脚本也无法建立可靠权限边界，因此不采用。

### 方案 C：只扩展本地启发式规则

调用成本最低，但面对自定义组件、模糊按钮文字和复杂章节嵌套仍会不断出现新特例，无法满足跨招聘系统的通用目标，因此只保留为高置信度快速路径和 AI 失败时的降级方案。

## 页面语义快照

### 元素范围

扫描当前页面或当前表单根节点中可见、可交互的：

- `input`、`textarea`、`select`；
- 单选框和复选框组；
- `contenteditable` 和 `role=textbox/combobox/listbox` 等 ARIA 控件；
- 文件上传控件；
- `button`、按钮型链接和 `role=button` 控件；
- 章节标题、字段标签、重复条目边界和与控件直接相关的短文本。

每次扫描为节点分配会话内 ID，例如 `section_3`、`row_2`、`field_17`、`control_8`。ID 通过元素引用和结构指纹维持稳定；DOM 更新后失效的 ID 不得继续执行。

### 字段描述

字段记录仅包含规划所需信息：

- 元素 ID、控件类型、输入类型、角色；
- `name`、`id`、`autocomplete`、`placeholder`、ARIA 标签；
- 显式标签、邻近短文本、所属章节、重复条序号和 DOM 顺序；
- 是否必填、禁用、只读、已填写；
- 下拉框或选项组的可见选项及对应选项 ID；
- 文件控件接受的类型，不包含文件内容和本地路径。

按钮记录可见文字、角色、所属章节、危险词标记和当前可用状态。页面文字作为不可信数据放入 JSON 数据区，提示词明确禁止把页面文字解释成系统指令。

### 隐私与体积限制

不发送原始 HTML、脚本、样式、隐藏字段值、用户已经输入的内容、Cookie、Local Storage、完整 URL 查询参数、附件、照片或 Base64。页面快照只发送结构和短语义文本。

资料继续使用现有经济模式：附件与图片始终不发送；身份证等敏感值只在页面确实出现对应字段时才按现有敏感字段策略提供。对字段、按钮、选项和文本长度设置硬上限，超大表单按章节分批规划。

## AI 规划协议

AI 必须返回符合 JSON Schema 的对象，不得返回选择器、脚本或自然语言执行指令：

```json
{
  "sections": [
    {
      "sectionId": "section_3",
      "profileCollection": "projects",
      "existingRows": 1,
      "desiredRows": 3,
      "addControlId": "control_8",
      "confidence": 0.98
    }
  ],
  "fieldMappings": [
    {
      "fieldId": "field_17",
      "profilePath": "projects.0.name",
      "optionId": null,
      "confidence": 0.97,
      "evidence": "section_label"
    }
  ],
  "actions": [
    {
      "type": "click",
      "controlId": "control_12",
      "purpose": "open_section",
      "confidence": 0.94
    }
  ]
}
```

允许的资料路径必须来自插件提供的路径目录。未知路径、未知 ID、重复占用同一字段、跨重复条目复用资料以及低置信度计划均被本地验证器拒绝。

## 两种执行模式

### 安全填写（默认）

允许：

- 写入文本、选择下拉/单选/复选选项；
- 为已配置的照片或简历附件设置文件上传控件；
- 在已确认的项目、实习/工作、教育和获奖章节中点击“新增一条”类控件。

禁止所有导航、下一步、保存、提交、删除和移除动作。

### 允许 AI 操作网页（用户主动开启）

在安全填写基础上额外允许：

- 打开与表单相关的折叠面板和弹窗；
- 切换表单内部标签页；
- 操作日期选择器、级联地区、搜索式下拉框；
- 点击招聘流程中的“下一步”，随后重新扫描新页面。

即使开启此模式，仍永久禁止：

- 最终提交简历、确认投递、报名或发送；
- 保存并提交、签署、付款、购买；
- 删除资料、删除经历、撤回申请；
- 打开外部任意链接、下载文件；
- 执行 AI 生成的 JavaScript、CSS、XPath 或键盘快捷命令。

该模式默认关闭。开关、站点授权和操作历史只保存在本机。界面明确显示当前模式，并允许用户随时停止。

## 本地安全验证与执行循环

执行器每次只执行一个结构动作：

1. 扫描当前页面并计算结构指纹。
2. 合并本地高置信度规则和 AI 计划。
3. 验证元素 ID、可见性、连通状态、章节归属和动作权限。
4. 执行一次点击或一次字段填写。
5. 使用 `MutationObserver` 和超时等待目标变化。
6. 重新扫描并确认预期变化，再继续下一步。

重复经历扩展必须观察目标章节的条目数量确实增加。点击无效果、出现未知页面、结构指纹异常、同一动作重复或达到步数上限时立即停止。默认设置每轮最大动作数，并以动作签名检测循环。

危险词和危险语义采用拒绝优先：即使 AI 将“保存并提交”标成下一步，本地验证器也必须拦截。最终提交按钮不提供任何可覆盖开关。

## 重复章节的顺序和去重

- 第 N 个项目条只使用 `projects[N]`，第 N 个工作/实习条只使用 `workHistory[N]`。
- 教育和获奖使用各自数组顺序，入学/毕业和获奖时间保持条目内绑定。
- AI 先报告现有条数、目标条数和添加控件；本地逐次扩展，禁止一次连续盲点多次。
- 每次新增后重新扫描，使用新条目的真实字段 ID 进行第二阶段映射。
- 同一资料路径在同一条目内只认领一次；已填写字段默认不覆盖，除非用户现有的覆盖设置明确允许。
- 页面条目多于资料条目时，剩余条目保持不变；资料条目多于可创建条目时，在结果中列为未填写。

## 调用成本与本地缓存

继续使用 `deepseek-v4-flash` 非思考模式和严格 JSON 输出。未知页面最多优先采用两阶段请求：第一阶段识别章节和结构动作，完成必要扩展后第二阶段映射全部可见字段。

缓存键由去敏感化站点标识、表单结构指纹、章节标题、字段类型和规范化标签组成，不包含字段值。缓存验证成功的映射和动作分类；结构未变化时优先本地重放，发生变化时仅重规划受影响章节。缓存和日志只存浏览器本机，并提供清除入口。

## 用户界面与结果反馈

自动填写设置新增：

- “AI 页面规划”开关；
- “允许 AI 操作网页”开关，默认关闭；
- 本站授权状态、停止按钮和清除本站映射入口；
- 本次识别章节数、创建条目数、填写字段数、跳过字段数和拦截动作数；
- 可展开的操作日志，显示动作目的、目标标签、结果与被拦截原因，但不显示身份证完整值等敏感资料。

## 失败与降级

- AI 请求失败或 JSON 无效：继续运行本地高置信度填写，不执行扩展网页操作。
- AI 引用不存在的 ID：忽略该动作并记录，不尝试猜测选择器。
- 添加按钮点击后条目数未增加：停止该章节，不重复点击。
- 页面发生导航或框架重载：旧计划全部失效，重新扫描。
- 自定义控件无法安全操作：标记为待手动填写，不通过模拟任意脚本绕过。
- 低置信度或冲突映射：跳过并在结果中显示字段标签。

## 测试与验收

- 扫描原生、ARIA、`contenteditable`、文件和按钮型控件，ID 在同一 DOM 中稳定。
- 快照不包含输入值、附件内容、Base64、Cookie、存储值和完整查询参数。
- 4399 风格 `.resume-module`、`.repeat-wrap`、`.add-entry` 能按资料数量逐条扩展。
- 手动增加条目后能重新扫描并按新 DOM 顺序填写。
- 三个项目和三段实习分别填入对应条目，简介、职责、业绩不跨条重复。
- 安全填写模式拒绝下一步；扩展模式允许下一步但仍拒绝最终提交、删除、撤回和付款。
- 页面标签中的提示注入文本不能改变系统规则或动作权限。
- 幻觉 ID、失效节点、无变化点击和动作循环能够安全停止。
- 页面结构缓存命中后不调用 AI；结构变化只使相关缓存失效。
- 运行全部单元测试、TypeScript 检查和 Chrome MV3 生产构建。
