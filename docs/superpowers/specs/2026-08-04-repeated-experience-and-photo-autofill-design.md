# 重复经历与求职照片自动填写修复设计

## 目标

修复国内招聘页中项目经历、实习/工作经历的条目数量、顺序和重复填写问题，并增加本机求职照片自动上传能力。

## 已验证页面特征

Moka 页面中的“添加”按钮自身只有“添加 / Add”，项目或实习语义位于外层区块标题中。项目单条包含约 9 个字段，实习单条包含约 14 个字段。旧实现要求按钮文本同时包含“添加”和“项目”，且仅为项目建立行索引，因此无法补足项目条目，也完全无法补足或顺序绑定实习条目。

## 设计

1. 使用区块标题锚定重复表单：先由“项目经历 / Projects”或“实习经历 / 工作经历 / Internship / Work experience”找到区块，再只在该区块内选择文本为“添加 / Add / 新增”的安全按钮。
2. 每次只点击一次添加按钮，等待区块内实际行数增加后重新扫描，最多补到资料条目数；不点击“添加学校全称”等其他区块按钮。
3. 对项目和实习分别建立独立的 DOM 顺序索引，将第 N 行绑定到 `projects.N.*` 或 `workHistory.N.*`。同一路径在同一行只填写一次，两个区块互不抢占。
4. 将项目描述拆分为“项目简介”和“项目中职责”：有项目符号时，首段作为简介、项目符号段作为职责；没有可拆分内容时只填简介，避免两栏重复。
5. 求职照片保存到独立的 `chrome.storage.local` 国内秋招资料中，默认不进入资料导出或 Google Drive。只匹配头像、证件照、个人照片等图片上传框，并明确排除简历、附件、成绩单等文件框。
6. 文件上传沿用浏览器 `File + DataTransfer` 方式，将本机保存的图片重建后写入招聘页文件输入框并触发 `input/change` 事件。

## 安全边界

- 添加按钮必须同时满足“按钮是添加动作”与“祖先区块是目标经历类型”。
- 照片仅接受常见图片 MIME，限制大小；照片与简历使用不同的语义分类。
- 自动填写不点击提交、保存、删除或取消按钮。
- 不在真实招聘页面进行提交测试。

## 验证

- Moka 风格的纯“添加 / Add”按钮能够在正确区块被识别。
- “添加学校全称”等相邻按钮不会被识别。
- 多条项目和实习按 DOM 顺序绑定到不同索引。
- 项目简介与职责输出不重复。
- 照片和简历上传框分别取得正确文件，模糊附件框不自动上传。
- 完成单元测试、类型检查和一次生产构建后交付。
