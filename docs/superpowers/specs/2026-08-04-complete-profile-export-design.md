# 完整个人资料导出设计

## 目标

“导出资料”生成一份可以完整恢复求职资料的本地 JSON 备份。备份包含普通简历资料、国内秋招资料、简历附件、求职照片、学习映射和投递历史，但不包含任何 AI API Key、Google Drive 令牌或其他登录凭据。

## 方案比较

1. **完整个人资料备份（采用）**：一个按钮导出全部求职资料与附件，不导出密钥。满足迁移需求，同时避免密钥泄露和意外扣费。
2. **完整浏览器镜像**：连 API Key、云盘令牌和界面设置一起导出。恢复最彻底，但明文 JSON 泄露风险过高，不采用。
3. **普通版与完整版双按钮**：安全边界清晰，但增加选择成本，也不符合“一次导出所有资料”的要求，不采用。

## 数据格式

导出格式升级为 `2.0`，保留原有字段并新增：

- `domesticProfile`：籍贯、政治面貌、婚姻状况、户籍、生源地、身高、体重、QQ、微信、完整身份证号、紧急联系人及电话、求职照片。
- `profile.documents`：继续携带简历和求职信的文件名、大小和 Base64 原文件内容。
- `learnedMappings`：网站字段学习记录。
- `applicationHistory`：投递历史。

明确排除：DeepSeek/Gemini API Key、AI 服务商凭据、Google Drive 令牌、云同步状态。界面在下载按钮附近提示：导出文件包含完整身份证号和附件，应妥善保管。

## 导入与兼容性

- 导入 `2.0` 文件时，在恢复普通 `profile` 的同时验证并恢复 `domesticProfile`。
- 导入旧 `1.0` 文件时继续按原逻辑工作，缺失的 `domesticProfile` 保持本机现状，不清空。
- 空资料直接导入和“合并/覆盖”导入都必须恢复国内秋招资料；国内资料作为一个完整的本机数据块恢复，不通过普通简历字段差异界面拆分。
- 非法或缺失的国内资料使用现有规范化函数降级为空字段，不执行任意对象写入。

## 错误处理与提示

- 没有普通资料但存在国内秋招资料时，仍允许导出。
- 下载失败时保持现有错误提示，不修改本机资料。
- 导出成功提示改为“完整资料已导出”。
- 导入说明改为可恢复完整资料，并再次提示备份中可能包含敏感信息。

## 测试

- 验证导出对象包含国内资料、完整身份证号、照片、简历附件、映射和历史。
- 验证导出对象不包含 DeepSeek/Gemini API Key 与 Drive 令牌。
- 验证 `2.0` 导入恢复国内资料和照片。
- 验证旧 `1.0` 导入仍兼容且不清空已有国内资料。
- 运行完整测试、TypeScript 检查和 Chrome MV3 生产构建。
