# 通用重复经历填写与简历解析降费设计

## 目标

修复两类根因：简历解析请求意外携带附件 Base64，导致单次费用偏高；国内招聘页使用非标准“添加”控件和动态条目，导致项目、实习经历无法自动扩展或手动扩展后仍无法填写。

实现不绑定 4399、Moka 或其他域名。适配依据只来自页面语义、控件行为和 DOM 结构。

## 方案比较

1. **通用语义与结构编排器（采用）**：把章节、添加控件、条目容器、字段扫描和顺序绑定拆成独立层。覆盖不同前端框架，安全边界可测试。
2. **招聘网站适配器**：按域名和 CSS 类写规则。短期快，但每个招聘系统都要维护，且页面改版即失效。
3. **AI 页面操作代理**：把 DOM 发给 AI 决定点击和填写。通用性表面较高，但每次填写都增加费用，并存在误点提交、删除的风险。

## 简历解析降费

### 请求数据

- DeepSeek 简历解析只发送标准化后的简历正文、文档超链接和固定提取规范。
- 不发送当前 `profile`。冲突检测继续由返回后的本地 `generateDiff` 完成。
- 永不发送 `documents`、求职照片、Base64、投递历史、字段学习记录或国内敏感资料。
- 文档正文去除重复空白和连续重复行；最大处理长度从 160,000 字符降为 60,000 字符。超过上限时明确提示用户使用精简简历，不进行可能遗漏尾部内容的静默截断。

### 输出预算

- 根据正文长度动态计算 `max_tokens`：`1800 + ceil(字符数 / 10)`，最少 2400，最多 6000。
- 保持 `deepseek-v4-flash`、非思考模式、JSON 输出和单次请求。
- 继续记录实际输入、输出、缓存命中与未命中 Token，便于用户核对账单。

## 通用重复章节架构

### 1. 章节识别

从章节标题、`legend`、ARIA 标签、前部文本和常见结构类识别项目、实习/工作、获奖等语义。章节边界支持标准 `section/fieldset`，也支持 `.resume-module`、`.form-module`、`.experience-section` 等组件容器。只读取章节开头的有限文本，避免其他章节污染。

### 2. 安全添加控件

候选包含标准按钮、链接、ARIA 按钮，以及文本精确匹配“添加/新增/增加/Add/New”的可见可点击容器，例如 `.add-entry`。泛化规则要求：

- 控件自身语义明确，或位于已确认的目标章节中。
- 排除包含删除、移除、提交、保存、取消、下一步等危险词的控件。
- 不自动点击整个表单、章节容器或包含多个交互子项的大容器。
- 每次只点击一次，并等待目标章节的条目数实际增加后才继续。

### 3. 条目边界

优先识别显式重复容器，如 `.repeat-wrap`、`.repeat-item`、`.experience-item`、带序号标题或删除控件的同级块。找不到时再使用现有字段数量和 DOM 分支启发式。条目按 DOM 顺序编号，并要求每个字段只属于一个最小有效条目。

### 4. DOM 新鲜度

扫描阶段保存字段与条目的结构指纹。执行填写前若字段数量、连接状态或条目指纹变化，则重新扫描并重新建立映射。这样自动点击产生的条目和用户在弹窗期间手动添加的条目都会进入本次填写。

### 5. 顺序绑定与去重

- 第 N 个项目条目只绑定 `projects[N]`；第 N 个实习/工作条目只绑定 `workHistory[N]`。
- 每个资料路径在同一条目内只允许认领一次，不跨条目复用。
- 项目名称、职务、开始时间、结束时间、简介、职责和业绩独立映射。
- 实习公司、部门、职位、时间、上司信息和内容独立映射；资料中没有的部门或上司信息保持空白。

## 项目数据模型

`ProjectEntry` 新增可选 `achievements` 字段。项目编辑界面、简历解析规范、验证器、差异预览、字段字典和取值器同步支持该字段。

- `description` 继续保存项目简介与职责原文，并提供现有 `summary`、`responsibilities` 虚拟路径。
- `achievements` 只保存简历中明确写出的结果、指标、奖项或交付成果。
- 页面“项目业绩/项目成果”优先映射 `projects.N.achievements`。
- 没有明确业绩时保持空白，禁止复制项目职责或简介。

## 失败处理

- 找不到安全添加控件时不点击，继续填写已有条目并标记剩余资料未填写。
- 点击后条目数未增加时立即停止该章节的后续点击，避免循环和误操作。
- 条目边界不确定时不进行索引绑定，保留人工选择入口。
- 自动填写永不点击删除、保存、提交、下一步或页面导航控件。

## 测试与验收

- 4399 形态：`.resume-module > form > .repeat-wrap + div.add-entry` 能识别、逐次扩展并按序绑定。
- Moka/标准形态：标准章节与按钮继续工作。
- 手动添加：扫描后新增条目，执行前能够重新扫描并填写。
- 安全性：教育章节的“添加”、删除、提交、保存等控件不会被项目/实习编排器点击。
- 去重：三个项目条目分别使用三个项目，简介、职责、业绩不相互复制。
- 解析请求：请求体不含当前资料、`documents`、`base64` 或照片；正文与输出预算有硬上限。
- 运行完整测试、TypeScript 检查和 Chrome MV3 生产构建。
